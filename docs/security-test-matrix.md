# Security test matrix

Living map from requirements in [`docs/spec/`](spec/README.md) to the tests
that actually verify them, with evidence locations (test file + name, or CI
run). Do not mark a row "done" without a real passing test backing it —
see `docs/spec/01-working-agreement.md` on not fabricating results. Status
is one of `missing`, `partial` (some real aspect of the requirement is
tested, but not the whole thing — say exactly what's left), `in progress`,
or `covered`.

**Status: Phase 3 (remaining bounded v1 features) done.** Unit/integration
tests now back the rows below that Phases 2-3 actually touch (OIDC login,
session, logout, namespace list, namespace overview, workload/service/
ingress/PVC list-detail, events, bounded pod logs with follow/cancellation,
and the frontend views for all of it). What's left `missing` is either
Phase 4 infrastructure (chart, CI, the mandatory multi-tenant/multi-replica
E2E suite against a real Capsule Proxy) or explicitly noted gaps below -
see `docs/implementation-plan.md`.
