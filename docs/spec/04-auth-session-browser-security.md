# Authentication, sessions, and browser security

> Part of the [TenantDeck kickoff specification](README.md).

- Authorization Code flow with PKCE S256, cryptographically random one-use state, nonce, bounded login-transaction lifetime, and session-fixation protection. Validate issuer, signature/allowed algorithms, audience, expiry and relevant OIDC claims with maintained libraries. Verify TLS and support explicit custom CA bundles.
- Fixed configured external URL and redirect URI. Do not construct trusted URLs from arbitrary Host or forwarding headers. Only relative, allowlisted post-login destinations; reject open redirects.
- Cookies: Secure, HttpOnly, host-only, Path=/, preferably __Host- prefix. Choose and document SameSite behavior that actually supports the OIDC callback. Do not blindly use Strict for the transient callback cookie; Lax with a top-level GET callback is a valid starting point. Isolate explicit loopback development exceptions; production must fail closed on insecure configuration.
- Require CSRF protection and exact Origin validation for state-changing local endpoints such as logout. Bind the callback to its login transaction rather than applying a blanket same-origin rule to the IdP callback. Disable cross-origin API access by default. Validate browser request provenance appropriately on authenticated reads without breaking same-origin requests where Origin is absent.
- Encrypt token-bearing session records with authenticated encryption using a separately provided key; never store that key in the same database record. Use random opaque session IDs, bounded TTLs, idle and absolute expiry. Support documented key rotation. Keep token material out of browser responses, URLs, logs, traces, metrics, and error pages.
- Refresh ID tokens server-side. Handle rotating refresh tokens and concurrent refresh across replicas using an atomic store/locking strategy. Validate returned tokens. Fail closed on invalid refresh; handle providers that omit a new ID token explicitly, never reuse an expired token or substitute an access token silently.
- Logout invalidates server-side state. Test that refresh cannot resurrect a deleted session. Explain that dashboard logout does not revoke already-issued Kubernetes JWTs or terminate the IdP SSO session unless explicitly integrated.
- Store unavailable means protected operations fail closed. No fallback to unverified cookies, in-memory production sessions, or alternate credentials.
- Strict CSP suitable for the built frontend, no third-party runtime scripts/CDNs, no unsafe HTML rendering of Kubernetes content. Treat logs, annotations, event messages and links as hostile input. Validate URL schemes. Add appropriate anti-framing, content-type, referrer and production HTTPS headers; use no-store on sensitive responses. Do not cache tenant data in a service worker.
